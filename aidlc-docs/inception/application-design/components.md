# Components

**Scope**: `auth-service` — 순수 인증/인가 API. API 게이트웨이는 별도 프로젝트이며 범위 밖 (2026-07-31 결정).

---

## AccountComponent

**책임**: 이메일/비밀번호 기반 계정 생명주기 관리

- 회원가입 (이메일/비밀번호), BCrypt 해시 저장
- 이메일 인증 (인증 링크 발급/검증, 계정 활성화)
- 비밀번호 재설정 (재설정 토큰 발급/검증, 비밀번호 변경 시 기존 Refresh Token 전체 무효화)
- 관련 스토리: US-101, US-102, US-104

**인터페이스 개요**: 회원가입/이메일 인증/비밀번호 재설정 관련 커맨드를 받아 계정 상태(MariaDB)를 변경하고, 이메일 발송이 필요한 경우 메시지 큐에 이벤트를 발행한다(Q5:B).

---

## SocialLoginComponent

**책임**: OAuth2 소셜 로그인 (Kakao, Naver, Google) 처리

- 각 제공자의 인가 코드(authorization code) 교환 및 사용자 정보 조회
- 신규 계정 생성 또는 기존 계정 연동 (동일 이메일 발견 시 "사용자 확인 후 연동" 정책 적용 — Q2:C)
- 관련 스토리: US-201, US-202, US-203

**인터페이스 개요**: 제공자별 콜백 처리 커맨드를 받아 AccountComponent의 계정 조회/생성 기능을 호출하고, 로그인 성공 시 TokenComponent에 토큰 발급을 위임한다.

---

## TokenComponent

**책임**: JWT 발급/검증/회전 및 다른 서비스가 사용할 토큰 검증 기능 제공

- Access/Refresh Token 발급 (역할 클레임 포함)
- Refresh Token 회전 및 재사용 탐지(토큰 패밀리 무효화)
- 로그아웃 시 즉시 무효화 (Refresh Token 폐기 + Access Token 블랙리스트 등록, Redis)
- 토큰 검증/인트로스펙션 API — 별도 API 게이트웨이 및 다른 백엔드 서비스가 이 서비스가 발급한 JWT의 유효성과 역할 클레임을 확인하는 데 사용 (FR-07)
- 관련 스토리: US-301, US-302, US-303, US-304

**인터페이스 개요**: 로그인 성공/토큰 갱신/로그아웃 커맨드를 받아 MariaDB(Refresh Token 메타데이터)와 Redis(블랙리스트)를 갱신하고, 외부 호출자를 위한 검증 조회 기능을 노출한다.

---

## RateLimitComponent

**책임**: 인증 엔드포인트에 대한 IP/계정 기준 Rate Limit 및 자동 IP 차단

- 인증 엔드포인트(로그인/회원가입 등)에 대한 IP 기준, 계정 기준 카운터 (Redis, TTL 기반, 다중 인스턴스 정합성 보장)
- 임계치 초과 시 자동 IP 차단, 쿨다운 경과 후 자동 해제 (TTL 만료)
- 관련 스토리: US-401, US-402, US-403, US-404, US-405

**인터페이스 개요**: 인증 관련 요청 전/후에 호출되어 허용 여부를 판단하고, 실패 시도를 기록하는 필터/인터셉터 형태로 다른 컴포넌트(AccountComponent, TokenComponent 로그인 경로) 앞단에 결합된다.

---

## AuthorizationComponent

**책임**: 이 서비스 자신의 보호된 엔드포인트에 대한 역할(RBAC) 검증

- 이 서비스가 노출하는 관리자 전용 기능(예: 사용자 관리) 등에 대해 서버 사이드 역할 검증 수행
- 미인증 요청에 대한 일관된 401 처리 (공개 엔드포인트 목록 관리: 회원가입/로그인/소셜 로그인 시작/토큰 갱신)
- 관련 스토리: US-501, US-502, US-603

**인터페이스 개요**: 이 서비스의 요청 처리 파이프라인(필터/인터셉터)에서 TokenComponent가 파싱한 역할 클레임을 참조해 접근 허용 여부를 결정한다. 다른 백엔드 서비스나 별도 게이트웨이의 인가 결정에는 관여하지 않는다 — 그쪽은 TokenComponent가 발급한 JWT의 role 클레임을 스스로 해석한다.
