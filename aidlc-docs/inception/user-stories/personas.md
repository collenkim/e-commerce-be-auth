# 페르소나 (Personas)

## 1. 구매자 (Buyer) — Role: `USER`
- **누구인가**: 이커머스 플랫폼에서 상품을 검색·구매하는 일반 회원
- **목표**: 빠르고 간편하게 로그인하고, 로그인 상태가 안전하게 유지되기를 원함
- **동기**: 매번 비밀번호를 입력하지 않고 소셜 계정으로 간편하게 로그인하고 싶음
- **불편한 점(Pain Point)**: 로그인 세션이 예고 없이 끊기거나, 다른 사람이 내 계정을 도용해도 알아채기 어려운 것
- **기술적 맥락**: 웹/앱 클라이언트를 통해 이 서비스의 인증 API를 호출해 토큰을 발급받고, 그 토큰으로 별도의 API 게이트웨이를 거쳐 다른 마이크로서비스에 접근

## 2. 판매자 (Seller) — Role: `SELLER`
- **누구인가**: 플랫폼에 입점하여 상품을 등록·관리하는 사업자 회원
- **목표**: 본인 소유의 상품/주문 데이터에만 접근하고, 구매자 전용 기능에는 접근할 수 없어야 함(또는 반대로 판매자 전용 기능이 구매자에게 노출되지 않아야 함)
- **동기**: 안정적인 세션 유지, 여러 관리 화면을 오가도 재인증 없이 작업하고 싶음
- **불편한 점**: 권한이 잘못 부여되어 다른 판매자의 데이터에 접근되거나, 반대로 정당한 접근이 차단되는 것
- **기술적 맥락**: 판매자 관리 콘솔(다른 마이크로서비스)이 이 서비스가 발급한 토큰의 역할(Role) 클레임을 신뢰하여 접근 제어를 위임함

## 3. 관리자 (Admin) — Role: `ADMIN`
- **누구인가**: 플랫폼 운영자로서 사용자/판매자/시스템 설정을 관리
- **목표**: 모든 관리자 전용 기능에 안전하게 접근하고, 일반 사용자는 절대 접근할 수 없어야 함
- **동기**: 강력한 권한을 가진 만큼, 오남용·탈취 시 빠르게 대응(토큰 무효화 등)할 수 있어야 함
- **불편한 점**: 관리자 권한 검증이 클라이언트 단에서만 이루어져 우회 가능한 것
- **기술적 맥락**: 서버 사이드에서 반드시 역할을 재검증하는 것을 전제로 관리 기능을 사용

## 4. 미인증 방문자 (Unauthenticated Visitor)
- **누구인가**: 아직 로그인하지 않은 사용자 — 회원가입/로그인 페이지에 진입했거나, 소셜 로그인을 시작하는 시점의 행위자
- **목표**: 이메일/비밀번호 또는 소셜 계정으로 빠르게 가입·로그인하고 싶음
- **동기**: 최소한의 입력으로 가입을 완료하고 싶음 (특히 소셜 로그인 선호)
- **불편한 점**: 인증 없이 접근 가능한 리소스가 무엇인지 불명확하거나, 인증되지 않은 요청이 애매하게 처리되는 것(어떤 API는 401, 어떤 API는 그냥 빈 데이터를 주는 등 일관성 부족)
- **기술적 맥락**: 이 서비스의 공개 엔드포인트(회원가입/로그인/소셜 로그인 시작/토큰 갱신 등)에 직접 접근하며, 그 외 엔드포인트는 일관되게 401로 거부되어야 함
